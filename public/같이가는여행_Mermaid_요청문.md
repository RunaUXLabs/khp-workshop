# 같이 가는 여행 · Mermaid 도식화 요청

### Mermaid로 UI 흐름과 데이터 흐름 그리기
[Mermaid Live Editor 열기](https://mermaid.live/edit)

공통주제 수강생은 아래 요청문을 사용하고, 자기 주제 수강생은 최신 `.md` 브리프의 문제·Must·역할·흐름·데이터로 바꿉니다.

### 사용하는 순서
1. 아래 자연어 요청을 **자신의 Claude·Codex 등 AI에 전달해 Mermaid 코드로 변환**합니다. Live Editor의 코드 입력란에는 자연어 요청문이 아니라 생성된 Mermaid 코드를 넣습니다.
2. [Mermaid Live Editor](https://mermaid.live/edit)에서 기존 예제 코드를 지우고, 코드 블록의 내용만 붙여 넣습니다. ` ```mermaid ` 같은 바깥 울타리는 제외합니다.
3. UI 흐름과 데이터 흐름은 **각각 별도의 그림**으로 확인합니다. 한 번에 한 도식의 코드를 넣으세요.
4. 오류가 나면 코드와 오류 문구를 AI에게 돌려주고 문법만 수정하게 합니다. 정상 흐름·분기·화살표가 브리프와 맞는지 직접 확인합니다.
5. 완성된 그림을 내보내거나 공유 링크를 확보하고, 원본 Mermaid 코드도 누적 브리프에 보관합니다.
6. **그림과 최신 브리프를 강사에게 전달해 함께 검토**합니다. 화면·분기·공개 범위를 고친 뒤 최종 Figma 요청에 반영합니다.

### 요청 1 · 공통주제의 UI 플로우차트
```text
‘같이 가는 여행’ 서비스의 UI에 반영할 사용자 흐름을 Mermaid 코드로 작성해 주세요.
Live Editor https://mermaid.live/edit 에 붙여 넣어 그릴 수 있는 flowchart TD를 사용하세요.
안정적인 영문 노드 ID와 큰따옴표로 감싼 한국어 라벨을 사용하세요.
먼저 그림 1개에 필요한 코드 블록만 출력하고, 그 아래 검토 질문 3개를 써 주세요.

[문제·범위]
여행 준비 조건이 채팅에 흩어지고 미응답이 섞여 확정 판단이 어려울 수 있다는 가설입니다.
핵심 화면은 ‘내 조건 확인’과 ‘함께 후보 비교’ 두 개입니다.
AI는 추출·정리·비교를 돕고, 사람은 자기 조건 확인·동의·최종 확정을 합니다.
예약·결제와 여행 추천 확장은 제외합니다. 모두 수업용 가설입니다.

[흐름]
시작 → 여행 대화·조건 입력 → AI 조건 추출 중 → 추출 성공 여부.
실패하면 실패 이유와 재시도 또는 직접 입력을 안내합니다.
성공하거나 직접 입력하면 ‘내 조건 확인’ 화면으로 갑니다.
원문과 조건 후보 대조 → 날짜·예산·필수 조건 및 공개 범위 수정 → 본인 확인.
누락이 있으면 수정으로 돌아가고, 확인하면 ‘함께 후보 비교’ 화면으로 갑니다.
후보별 조건 충족·충돌·미확인과 사람별 응답 상태를 보여 줍니다.
충돌 또는 미확인이 있으면 확정 차단 이유를 표시하고 조건 조정 또는 응답 요청으로 갑니다.
미응답은 동의가 아닙니다. 응답 요청은 화면의 사용자 행동으로만 나타내세요.
조건을 조정하면 영향받는 조건 확인과 기존 동의를 다시 확인합니다.
조건 충돌·미확인이 해소되면 각자 ‘이 후보에 동의’를 선택합니다.
선택 후보에 대해 전원의 명시적 동의가 모였는지 판단합니다.
아직이면 대기 상태로, 모였으면 준비자가 ‘최종 확정’을 실행합니다.
확정 이후 조건 변경도 영향받는 확인·동의를 다시 받는 흐름으로 연결합니다.

[표현·검수]
화면, 처리, 판단 분기를 구분하고 분기 화살표에 예/아니오를 붙이세요.
누가 행동하는지 라벨에 표시하고 AI 초안·본인 확인·동의·확정을 혼동하지 않게 하세요.
서연의 예산 30만원 이내는 공유할 수 있지만 비공개 사유는 공유 UI에 표시하지 않습니다.
위 조건을 넘는 기능을 추가하지 마세요.
```

### 요청 2 · 공통주제의 데이터 흐름
```text
‘같이 가는 여행’의 데이터 흐름을 별도 Mermaid flowchart LR 코드로 작성해 주세요.
Live Editor https://mermaid.live/edit 에 붙여 넣을 수 있어야 합니다.
영문 노드 ID와 큰따옴표로 감싼 한국어 라벨을 사용하세요.
코드 블록 1개와 그 아래 데이터 공개 범위 점검 질문 3개를 출력하세요.
정식 DFD 표기 전체를 구현하기보다 데이터의 출처·처리·저장·표시를 읽기 쉽게 나타내세요.
아래 저장소는 수업용 설계안이며 실제 서버가 구현됐다는 뜻은 아닙니다.

[주체·입력]
참여자(지수·민호·서연·도윤), 준비자 지수, AI 처리, 시스템 처리,
‘내 조건 확인’ UI, ‘함께 후보 비교’ UI를 구분합니다.
입력은 여행 대화·날짜·예산·필수 조건·공개 범위입니다.
S01 지수의 조건 재정리, S02 민호의 토요일 가능·금요일 불가,
S03 서연의 예산 30만원 이내·사유 비공개,
S04 도윤의 코스 위임·장거리 이동 기피, S05 미응답 대기는 합성자료입니다.

[데이터 이동]
사용자가 공개 범위를 선택한 입력 → 시스템의 AI 전달 전 공개 범위 검사.
AI 전달은 필요한 공개 가능 텍스트만 포함합니다. 비공개 사유는 AI 입력에서 제외합니다.
필요하지 않은 비공개 사유는 수집·저장하지 않는 설계로 둡니다.
AI → 추출 초안(값·원문 참조·확인 필요 상태) → 본인 전용 조건 확인 UI.
사람의 수정·본인 확인 → 확인된 조건 저장소.
공유가 허용된 확인 조건만 → 시스템 후보 비교 → 공유 후보 비교 UI.
참여자별 응답 상태 → 후보 비교 UI. 미응답과 명시적 동의를 별개 값으로 다룹니다.
후보에 대한 개인 동의 → 동의 상태 저장소.
준비자의 최종 확정 요청 + 최신 조건·동의 상태 → 시스템 확정 가능 여부 검사.
충돌·미확인 없이 선택 후보에 전원이 동의했을 때만 확정 상태 저장소와 공유 UI로 보냅니다.
조건 수정 → 조건 변경 이력 → 영향받는 확인·동의를 재확인 필요로 변경 → 각 UI에 반영.
AI가 동의나 확정 값을 직접 쓰는 화살표는 만들지 마세요.

[표현·검수]
입력/처리/저장소/UI를 구분하고 모든 화살표에 전달하는 데이터명을 적으세요.
원본 입력은 본인 접근 범위와 공유 가능 범위를 구분하세요.
공유 UI·원문 미리보기·오류 출력으로 비공개 사유가 새는 경로가 없어야 합니다.
예약·결제·추천 데이터와 외부 연동은 추가하지 마세요.
```

### 그림을 받은 뒤 확인할 것
- UI 플로우의 각 행동·분기를 두 화면의 버튼·상태·문구로 옮길 수 있나요?
- UI에 보이는 값이 어떤 입력·확인·저장 상태에서 오는지 데이터 그림으로 설명되나요?
- AI 초안이 사람의 동의·확정으로 바로 넘어가거나 비공개 정보가 공유되는 화살표는 없나요?

**산출물:** UI 흐름도 1개 + 데이터 흐름도 1개 + 두 원본 코드 + 검토 후 수정한 브리프. 그림은 화면 설계의 입력이며, 실제 기능 구현이나 사용자 검증 완료를 뜻하지 않습니다.
